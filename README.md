# سایت شخصی آکادمیک: Amir Arman Nejati

سایت استاتیک ساده با HTML، CSS و کمی JavaScript. نه فریم‌ورکی دارد، نه مرحلهٔ build. فایل‌ها را ویرایش می‌کنید و همان‌ها منتشر می‌شوند.

## ساختار پوشه‌ها

```
website/
├── index.html              اسکلت صفحه و تگ‌های meta (معمولاً دست نمی‌خورد)
├── content.js              همهٔ محتوای سایت (فقط همین را ویرایش کنید)
├── .nojekyll               به GitHub Pages می‌گوید فایل‌ها را بدون پردازش منتشر کند
├── README.md
└── assets/
    ├── css/style.css       ظاهر سایت و رنگ‌های حالت روشن/تیره
    ├── js/main.js          محتوای content.js را داخل صفحه می‌چیند
    ├── docs/               CV.pdf و گزارش‌های PDF پروژه‌ها
    └── img/
        ├── favicon.svg, favicon-32.png, apple-touch-icon.png
        ├── og-image.png    تصویر پیش‌نمایش لینک در ایمیل و لینکدین (1200×630)
        └── projects/       تصاویر پروژه‌ها (placeholder.svg تصویر پیش‌فرض است)
```

## ویرایش محتوا

همهٔ متن‌ها در `content.js` هستند. فایل را با یک ویرایشگر متن (مثلاً VS Code) باز کنید و مقدارهای داخل گیومه را عوض کنید.

چند نکته:

- هر متنی که با `[TODO: ...]` شروع شود روی سایت با پس‌زمینهٔ زرد دیده می‌شود تا یادتان نرود. قبل از فرستادن لینک برای استادها همه را پر یا حذف کنید.
- لینکی که آدرسش خالی (`""`) یا TODO باشد کلیک‌پذیر نیست، پس لینک شکسته ساخته نمی‌شود.
- بین آیتم‌ها ویرگول لازم است. اگر بعد از ویرایش صفحه خالی شد، تقریباً همیشه یک ویرگول یا گیومه جا افتاده است. کنسول مرورگر (F12) خط مشکل‌دار را نشان می‌دهد.

### عکس پروفایل

1. عکس را (ترجیحاً مربعی، حدود 400×400 پیکسل و زیر 150 کیلوبایت) با نام `profile.jpg` در `assets/img/` بگذارید.
2. در `content.js` بنویسید: `photo: "assets/img/profile.jpg",`

تا وقتی `photo` خالی باشد، دایره‌ای با حروف AN نمایش داده می‌شود.

### اضافه کردن پروژهٔ جدید

در `content.js` به لیست `projects` بروید، یک بلوک `{ ... }` کامل را کپی کنید، اول لیست بگذارید (بعدش ویرگول) و مقدارها را عوض کنید:

```js
{
  title: "عنوان پروژه به انگلیسی",
  type: "Course project",            // یا "Research"
  context: "Heat Transfer",          // نام درس یا آزمایشگاه
  date: "Mar 2027",
  description: "دو سه جمله دربارهٔ کاری که کردید و نتیجه‌اش.",
  tools: ["Python", "OpenFOAM"],
  image: "assets/img/projects/heat-sink.png",   // یا "" برای تصویر پیش‌فرض
  imageAlt: "Temperature contour of the heat sink",
  links: [
    { label: "GitHub", url: "https://github.com/USERNAME/heat-sink" },
    { label: "Report (PDF)", url: "assets/docs/heat-sink-report.pdf" }
  ]
},
```

- تصویر را در `assets/img/projects/` بگذارید. نسبت 16:9 بهتر از همه جا می‌افتد. اسم فایل را انگلیسی، با حروف کوچک و بدون فاصله بنویسید (مثل `heat-sink.png`).
- گزارش PDF را در `assets/docs/` بگذارید.
- برای حذف یک لینک، کل `{ label: ..., url: ... }` را پاک کنید. اگر پروژه هیچ لینکی ندارد بنویسید `links: []`.

### اضافه کردن مقاله

تا وقتی `publications: []` خالی است، بخش Publications متن «In preparation.» را نشان می‌دهد. نمونهٔ یک مقاله به صورت کامنت داخل `content.js` هست. آن را از کامنت بیرون بیاورید و داخل `[]` بگذارید.

### فایل CV

فایل را دقیقاً با نام `CV.pdf` در `assets/docs/` بگذارید. اگر اسم دیگری می‌خواهید، `cv.file` را در `content.js` عوض کنید. تاریخ نسخه را هم در `cv.updated` بنویسید.

### عنوان بخش‌ها و منو

عنوان بخش‌ها (مثل «Research Interests») و منوی بالای صفحه در `index.html` هستند، چون جزو ساختار صفحه‌اند و نه محتوا.

## دیدن سایت روی کامپیوتر خودتان (قبل از انتشار)

ساده‌ترین راه: دوبار کلیک روی `index.html`. سایت در مرورگر باز می‌شود و همه‌چیز کار می‌کند.

راه دقیق‌تر که مثل سرور واقعی رفتار می‌کند: اگر Python نصب است، در پوشهٔ سایت ترمینال باز کنید و بزنید:

```bash
python -m http.server 8000
```

بعد در مرورگر بروید به `http://localhost:8000`. برای بستن سرور در ترمینال `Ctrl+C` بزنید. (روی بعضی سیستم‌ها به جای `python` باید `python3` بنویسید.)

برای دیدن نمای موبایل در Chrome، کلید F12 و بعد `Ctrl+Shift+M` را بزنید و عرض 375 را انتخاب کنید.

## انتشار روی GitHub Pages

فرض کنید نام کاربری گیت‌هاب شما `USERNAME` است. سایت روی `https://USERNAME.github.io` منتشر می‌شود.

### روش ۱: از طریق سایت گیت‌هاب (بدون خط فرمان)

1. وارد github.com شوید. بالا سمت راست روی **+** و بعد **New repository** بزنید.
2. نام مخزن را **دقیقاً** `USERNAME.github.io` بگذارید (با نام کاربری خودتان، حروف کوچک). نوع را **Public** بگذارید و **Create repository** را بزنید.
3. در صفحهٔ مخزن روی لینک **uploading an existing file** بزنید.
4. **محتوای** پوشهٔ `website` را بکشید و رها کنید، نه خود پوشه را. یعنی `index.html` باید در ریشهٔ مخزن باشد، کنار `content.js` و پوشهٔ `assets`.
   - فایل `.nojekyll` در ویندوز و مک ممکن است مخفی باشد. اگر آپلود نشد، بعداً با **Add file → Create new file** فایلی به نام `.nojekyll` با محتوای خالی بسازید.
5. پایین صفحه **Commit changes** را بزنید.
6. بروید به **Settings → Pages**. در قسمت **Build and deployment**، گزینهٔ Source را روی **Deploy from a branch** بگذارید، Branch را `main` و پوشه را `/ (root)` انتخاب کنید و **Save** بزنید.
7. یکی دو دقیقه صبر کنید و `https://USERNAME.github.io` را باز کنید. وضعیت انتشار در تب **Actions** دیده می‌شود.

برای به‌روزرسانی بعدی: در مخزن روی فایل `content.js` بزنید، آیکون مداد را بزنید، ویرایش کنید و Commit کنید. برای فایل‌های جدید (عکس، PDF) از **Add file → Upload files** استفاده کنید. چند دقیقه بعد سایت به‌روز می‌شود.


### بعد از اولین انتشار: پیش‌نمایش لینک

لینکدین، تلگرام و ایمیل برای ساختن پیش‌نمایش، JavaScript را اجرا نمی‌کنند و فقط تگ‌های `<meta>` بالای `index.html` را می‌خوانند. پس:

1. آدرس سایت (`https://armannejati3264.github.io`) در تگ‌های canonical، `og:url` و `og:image` در `index.html` تنظیم شده است. اگر روزی دامنه یا نام کاربری عوض شد، این سه جا را به‌روز کنید.
2. اگر توضیح کوتاه سایت را عوض کردید، `description` و `og:description` را هم همان‌جا عوض کنید.
3. پیش‌نمایش را با [LinkedIn Post Inspector](https://www.linkedin.com/post-inspector/) بررسی کنید. اگر لینکدین نسخهٔ قدیمی را نشان داد، همین ابزار کش آن را تازه می‌کند.
